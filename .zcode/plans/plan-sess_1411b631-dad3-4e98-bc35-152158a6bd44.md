## Phase 2 — Mémoire du tuteur vocal — *réutiliser les tools existants, rien de neuf*

La couche mémoire est déjà thread-agnostic (namespaces keyés par `user_id` seulement) : le worker la branche directement.

**(a) Identité** : le worker tire `user_id` de `participant.identity`, que le backend force déjà (`api/livekit.py:56`) — jamais confiance en une valeur client.

**(b) Contexte injecté au démarrage de la session** (fast path, pas de tool-call) :
- `read_profile(user_id)` (`memory.py:243`) + `memory_overview_for_api(user_id)` (`memory.py:847`) → le prompt système est enrichi : "Tu tutoies X, il préfère Y, points forts Z".
- `read_learning_profile(user_id)` (`learning_profile.py:89`) → niveau de maîtrise et `MAX_OBSERVATIONS=50` dernières observations.

**(c) Tools LiveKit exposés à l'agent** — wrapper mince autour des tools LangChain existants (`livekit.agents` function tools) :
- `get_user_profile` / `update_user_profile` (`tools/__init__.py:88,110`)
- `get_user_memory` / `save_user_memory` / `update_user_memory` / `delete_user_memory` / `search_user_memory` (`tools/__init__.py:140-228`, `memory_tools` L248)
- `search_facts` direct (`memory.py:741`, hybride `0.60*lexical + 0.40*semantic`, L121-156) pour la pertinence.

**(d) Écriture en fin de tour** — le worker apprend de la session vocale :
- `save_fact(user_id, category, content, source="user")` (`memory.py:458`) — **déclinaison automatique déjà gérée** (seuil `DEDUP_THRESHOLD = 0.72`, L35).
- `update_profile_from_observation(...)` (`learning_profile.py:392`) → le profil d'apprentissage est mis à jour par la voix, comme par le texte.
- Transcript POSTé au thread existant → la conversation vocale apparaît dans l'historique clavier.

**(e) Discipline imposée** : toujours passer par les fonctions publiques (`_store_lock` est module-level, sqlite ne supporte pas le multi-threading concurrent) — jamais de `store.put`/`store.get` direct. Isolation `user_id` garantie par `_profile_namespace()` (`memory.py:64-66`).

## Phase 6 — Dictée pour la transcription écrite (composer)

Approche **LiveKit** (pas WebSpeech navigateur) : la dictée vient du STT Inference.
- En session vocale, le transcript utilisateur est accumulé ; bouton **"Insérer dans le composer"** → `aui.composer.setText(texte)` + `send()` (même mécanisme officiel que `ActivityTrigger`, `thread.aui.tsx:315-319`).
- `ComposerPrimitive.Dictate` (`thread.aui.tsx:332`) ouvre `/voice?mode=dictate&return=/assistant` : se ferme après la première phrase retranscrite et remplit le composer.
- `adapters.speech` : la parole agent est portée par la session vocale (agent qui parle), pas un TTS navigateur.
